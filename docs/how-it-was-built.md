# How TurnBase was built

TurnBase is also an experiment: a whole system (a platform, a sandboxed game runtime, an SDK, a frontend and two
games) built by AI coding agents working under a written process, with one human owner deciding what matters.
This page says how that process works, what it produced, and what went wrong. Every claim links to the file or
commit it comes from; the numbers are produced by a script, not remembered.

## 1. Spec first

Nothing was coded until the design existed in writing, in four layers, each pointing at the one above:

1. **Requirements** ([`requirements/`](requirements/INDEX.md)): what the system must do, as identified, testable
   statements (`FR-*`, `NFR-*`).
2. **Specifications** ([`specs/`](specs/INDEX.md)): how it is designed: API, platform, flows, the gRPC contract,
   the Game Host, the SDK, the manifest, both frontends, deployment.
3. **Decisions** ([`decisions/`](decisions/INDEX.md)): one ADR per cross-cutting choice and its reason, for example
   [0005](decisions/0005-game-sandbox-espresso-spike.md) (an Espresso spike gated the Game Host design) and
   [0006](decisions/0006-game-trust-model-java-official-only.md) (only official games may ship Java backends).
4. **Work items** ([`implementation/registry.md`](implementation/registry.md)): one `IMP-*` item per unit of
   build work, each with a *Read first* list (the minimum set of documents that determine it) and a *Done when*
   clause that can be checked without judgement. The shape and the reasoning are in
   [`implementation/INDEX.md`](implementation/INDEX.md).

The reason is the executor. Agents run at modest reasoning effort and start every session cold. They are good at
building to a precise brief and poor at reconstructing an architecture from seventeen documents, so the corpus is
made to need no reconstruction. A specification defect is fixed in the specification, never in code
(see the guard-rails below).

## 2. The agent workflow and its guard-rails

A session reads [`STATUS.md`](../STATUS.md) and [`CLAUDE.md`](../CLAUDE.md), takes one item, and ends with a
checklist. What keeps that honest is mechanical wherever it could be:

| Guard-rail | What it does | Where |
|---|---|---|
| `work-item` skill | Claim the item in the register first, read exactly its read-list, build to the *Done when* clause, mark `PARTIAL` (with a `Remaining:` line) rather than `DONE` when it is not | [`.claude/skills/work-item`](../.claude/skills/work-item/SKILL.md) |
| `spec-defect` skill | The moment two documents disagree, stop and open a gate; do not reconcile in code | [`.claude/skills/spec-defect`](../.claude/skills/spec-defect/SKILL.md) |
| `check-corpus.py` | Nine structural checks over the docs (links, requirement citations, index coverage, register shape, counts, code maps, code references); exit 1 on failure | [`scripts/check-corpus.py`](../scripts/check-corpus.py) |
| `git-land.sh` | The one allowlisted way to commit, fast-forward merge, push and delete branches, ending in `GIT_STATE: CLEAN` or `DIRTY` | [`scripts/git-land.sh`](../scripts/git-land.sh) |
| `pre-push` hook | Runs the corpus checks and the proto and manifest-schema drift guards before anything leaves the machine | [`.githooks/pre-push`](../.githooks/pre-push) |
| Static analysis in the build | Spotless (`google-java-format`), Error Prone with NullAway ([ADR-0015](decisions/0015-static-analysis-error-prone-nullaway.md)), Spring Modulith failing the build when a feature reaches into another's internals ([ADR-0014](decisions/0014-modular-monolith-spring-modulith.md)), JaCoCo over merged unit and integration data | [`implementation/conventions.md`](implementation/conventions.md) |

The loop itself (a script that starts one non-interactive session at a time, with a permission allowlist and a
stop hook) is in [`scripts/autonomous-work-loop.sh`](../scripts/autonomous-work-loop.sh).

Two rules turned out to carry more weight than expected. **One item per session, closed or marked `PARTIAL`**,
because a half-finished item written up as done unblocks its dependents against code that does not exist. And
**the register is the only protection against two sessions picking the same item**, so the claim is the first commit.

## 3. Reviews

Eight review rounds ([`reviews/`](reviews/)), each reduced after closing to its INDEX. Several were black-box: a
session drove the running stack through a browser and wrote down what a player would see, independent of what the
register said was done.

| Round | What it found |
|---|---|
| [2026-07-02 MVP readiness](reviews/2026-07-02-mvp-readiness/INDEX.md) | Gaps in the Phase 0 corpus; six strategic decisions, ratified as ADR-0001 to 0005 |
| [2026-08-16 implementation readiness](reviews/2026-08-16-implementation-readiness/INDEX.md) | 23 blockers to implementing at low effort; all closed before Phase 1 began |
| [2026-10-01 MVP implementation review](reviews/2026-10-01-mvp-implementation-review/INDEX.md) | The API and Game Host worked; the frontend room views were placeholders, and two `DONE` items satisfied only their narrow clause |
| [2026-10-03 regression review](reviews/2026-10-03-mvp-regression-review/INDEX.md) | 10 of 11 first-round findings closed; three views returned 500 |
| [2026-10-04 completeness audit](reviews/2026-10-04-mvp-completeness-audit/INDEX.md) | Every view and the play loop worked; friend invitations were not built |
| [2026-10-10 end-to-end security audit](reviews/2026-10-10-e2e-security-audit/INDEX.md) | An ownerless-game upload was authorized and a wildcard STOMP subscribe leaked another user's queue |
| [2026-10-29 M18 reassignment](reviews/2026-10-29-m18-reassignment/INDEX.md) | `OQ-5` by measurement: lazy room reassignment beat eager on the decision rule, neither had a correctness failure, and eager's code was removed |
| [2026-11-04 refinement spike](reviews/2026-11-04-refinement-spike/INDEX.md) | A sound base; cost, legibility and release hygiene needed work (this page is finding RS-06) |

Each round's findings became work items (`IMP-M7` to `M10`, `M20`), so a review is not a report that sits in a
folder; it is the next milestone.

## 4. Evidence

- **Load and scalability.** Six scenarios against the Helm install on one 16-CPU laptop node, then re-run after the
  fixes. Phase A found a ceiling of 70 concurrent game pairs, the platform pod and Postgres (not the Game Host) as
  the limit, and 18 findings; after the fixes the ceiling was 80 pairs. One finding was dissolved by measurement:
  the 10 s WebSocket stall "about every 300 s" was the load generator's DNS re-resolve, not the product
  ([`2026-10-21-m16-stall.md`](../loadtest/reports/2026-10-21-m16-stall.md)). The 500-session and 5,000-socket
  targets were **not reached**, and the summary says so. See
  [`loadtest/reports/SUMMARY.md`](../loadtest/reports/SUMMARY.md) and the follow-ups in
  [`specs/backlog.md`](specs/backlog.md).
- **Test cost.** [`scripts/test-cost.sh`](../scripts/test-cost.sh) reads existing reports and prints the
  slowest classes. The baseline of 2026-11-05 ([`e1129c5`](https://github.com/turnbase-platform/turnbase/commit/e1129c5))
  put the platform's 381 integration tests at 614.5 s of class time, and showed the Game Host's "unit" phase at
  117 s because three tests booted Espresso. Two items followed: one cached Spring context per test family
  (`TwoInstanceIT` roughly 104 s to 41 s; [`b5f7239`](https://github.com/turnbase-platform/turnbase/commit/b5f7239),
  class-time sum 614.5 s to 391.8 s, of which about 110 s were DNS timeouts of that machine), and a `perf` tag that
  moved the pure measurements out of the default build ([`af1b704`](https://github.com/turnbase-platform/turnbase/commit/af1b704)).
  In the same pass one redundant test was removed, with the covering test named in the commit
  ([`31bb40b`](https://github.com/turnbase-platform/turnbase/commit/31bb40b)).
- **Coverage.** The rule is more than 70% line coverage on critical paths, measured over merged unit and
  integration data ([`conventions.md`](implementation/conventions.md) *Coverage*). It is enforced by the build,
  so the figure is whatever each repository's `./mvnw verify -Pintegration` reports.
- **Security.** The 2026-10-10 audit above, plus a CVE gate (Trivy) in every pipeline, which is why
  [ADR-0016](decisions/0016-spring-boot-4-migration.md) moved both services to Spring Boot 4.1: two CRITICAL
  `spring-webmvc` CVEs had no fix on the 3.5 line.

## 5. What went wrong, and what changed

- **Pull requests (2026-09-05).** The project required a PR for every change. On a solo repository with no second
  reviewer, it produced eight open PRs and eleven abandoned branches, none awaiting a review. PRs were suspended;
  a branch is now merged and deleted in the session that created it
  ([ADR-0012](decisions/0012-repo-strategy-polyrepo-submodules.md) *Pull requests are suspended*,
  [`e1a3426`](https://github.com/turnbase-platform/turnbase/commit/e1a3426)).
- **`BLOCKED` from stale memory (session 87).** An agent reported an item blocked on a missing CI secret using a
  carried-over summary instead of checking; the secret had been provisioned since. The fix was a rule in
  `CLAUDE.md`: re-run the actual check before reporting `BLOCKED`
  ([`1ea8996`](https://github.com/turnbase-platform/turnbase/commit/1ea8996)). The same failure appeared again in
  a `PARTIAL` item whose `Remaining:` line said a compose stack did not exist when it did, which is why the
  `work-item` skill now says to check that line against the repository.
- **Items "done" that were not usable.** The 2026-10-01 black-box run found two frontend items marked `DONE`
  that satisfied their narrow clause and not the requirements they claimed. The later rounds
  drove the running product through a browser.
- **The Java language server (2026-11-07).** `jdtls` worked, but on first use it imported the Maven project into the
  same `target/classes` Maven builds into; a `verify -Pintegration` running at the time lost classes mid-run
  (34 failures). It is disabled until it can build elsewhere ([`CLAUDE.md`](../CLAUDE.md) *Language servers*).
- **CI that was not running (2026-11-04).** The spike found GitHub refusing most runs for billing, and a pinned
  submodule commit CI had never verified, against the project's own rule. M20 made the build judged locally and
  honest, and CI is green again on the repositories listed in [`STATUS.md`](../STATUS.md).
- **The readiness audit.** The 2026-08-16 audit counted 23 blockers in a corpus declared complete the day before.
  Closing them (three design sessions and one scope cut) is why Phase 1 items rarely stopped on a missing
  decision.

## What this does not show

One human reviewed direction, not every line: the owner set scope, approved ADRs and read the review verdicts.
The load numbers are single-node and optimistic by the summary's own account. Test counts say how many tests
exist, not how good they are; the refinement spike found 2 of 680 platform test methods without an assertion and
could not settle how much overlap remained. The second game, a full implementation of a commercial board game, is
withheld until its publisher answers ([README](../README.md)).
